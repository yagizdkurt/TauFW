# Legacy analysis archive

For future additions and retirements, follow the [legacy code policy](../../docs/LegacyCode.md).

Archived on **2026-10-13** as `LegacyAnalyses/`, then moved to `Legacy/OldAnalysis/` on **2026-10-14**. This directory holds 33 one-off or retired analysis files whose relocation has no identified executable consumer in this checkout. These files are reference material; moving them does not certify that they run.

## Layout and move decisions

Files sit directly in their data-taking-year folders, without component or analysis subfolders. Every file has a `LEGACY CODE - <TYPE>` comment banner with its original location, year evidence, purpose and retirement reason. Types distinguish analysis, plotting, correction, postprocessing, postfit and diagnostics code; retirement does not imply that every file was single-use.

Year assignment uses input campaigns, era settings, correction mappings and supported CLI eras. Authoring dates and algorithm names such as DeepTau2017 are not data-year evidence. Year ranges hold multi-year Run 2 code; `MultiYear` holds a plotter spanning both runs. `YearIndependent` holds studies without a data-taking-year requirement; `UnknownYear` holds producers whose input campaign cannot be established. Files are stored once, rather than duplicated into each supported year.

All executable source text is preserved apart from comment banners. Generated `__pycache__` files were left alone and are excluded from both inventories. Old `TauFW.*.legacy` import paths for these moved files are no longer available; none is imported by repository code. External scripts or personal channel configurations must be updated if they used those paths. Git can trace the original history with `git log --follow <new-path>`.

## Dependency and path audit

The audit reviewed all 934 tracked paths and scanned 601 source/configuration text files on disk, including ignored local configuration and inventory files (excluding Git internals, caches and generated run areas). Searches covered filenames, module names, imports, shell invocations, ROOT macro loading, configuration paths and sibling relationships. No executable consumer outside the moved set was found. The ignored `LocalR/architecture/inventory.json` contains historical inventory records, not workflow instructions. Generic `plot2D` functions in b-tag utilities and `plot2DScan_MultiDimFit.py` are separate implementations.

The scripts use installed `TauFW`/CMSSW packages, absolute campaign inputs, command-line inputs or paths relative to the working directory. None derives input locations from its own `__file__`. The LQ and g-2 producers obtain their branch-selection file from `TauFW.PicoProducer.workers.moddir`, which remains unchanged. Moving them does not change that lookup.

Keep the original working directory when inspecting or adapting a script. Plotter studies that import `config.samples` need `Plotter/` on `PYTHONPATH`, and relative `python/macros/`, `plots/` and ROOT input paths are resolved from `Plotter/`. Fitter studies resolve `TauES_ID/config/`, `postfit_*` and `log/` from `Fitter/`. Pico cutflow examples expect `PicoProducer/` or explicit data paths. For example, after activating TauFW:

```bash
cd Plotter
PYTHONPATH=".:${PYTHONPATH}" python3 ../Legacy/OldAnalysis/2016-2018/plot_differential.py --help
```

This is a path example, not a successful runtime check. Existing defects remain: `takeZmu.py` has an indentation error and an undefined `dm`; `plot_mvis_uncorr_corr.py` omits `import os`; some plotting scripts have missing initialization/imports; g-2 macros require external ROOT payloads at their original absolute paths. The tuple/cutflow repair scripts modify ROOT files when run, so they were not executed during this cleanup.

## Validation

All 33 archived files have one banner and one inventory entry, at a flat year-group path. Removing each banner reproduces its source before this regrouping (with the earlier example banner removed). Python AST comparisons pass for all 30 parseable Python files; takeZmu retains its existing indentation error. Both ROOT macros preserve their full original source beneath C++ comment banners. Old component directories are gone, current documentation links are updated, and no moved entries remain in docs/Refactor-2025/Legacy.md. No ROOT/CMSSW analysis jobs or broad test suite were run.
