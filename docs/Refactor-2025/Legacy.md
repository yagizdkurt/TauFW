## How to read the reasons

The retirement decisions come from [Fitter's legacy README](../Fitter/Legacy/README.md), [PicoProducer's legacy README](../PicoProducer/python/legacy/README.md), [Plotter's legacy README](../Plotter/Legacy/README.md) and [the refactor change log](Refactor-2025.md). The descriptions below also use the files' comments, functions, commands and configurations. “Unreferenced” describes the cleanup's recorded findings about maintained workflows; it does not mean a file has never been useful or has no external users. A one-off study can be legacy without being broken.

PicoProducer files were archived on 2026-10-12; Fitter and Plotter files on 2026-10-13. They were kept for reference rather than deleted. Uppercase `Legacy/` holds scripts and configurations; lowercase `python/legacy/` holds package modules and macros. Preserving a Python package path does not guarantee that its dependencies or runtime behavior still work. The legacy READMEs describe location-dependent imports and paths that may require repair.

README files and `__init__.py` explain or organize the archive; they were not retired analysis implementations. Bytecode files are generated artifacts, with no documented individual retirement decision. Their reason for being here is inferred from their `__pycache__` location and corresponding archived source. Each has a separate entry below.

Two details need care when comparing this inventory with older notes. `run_createroot_TES.py` passes an ordinary string containing `{era}`, `{jet_wp}` and `{ele_wp}` to `hadd`. Those placeholders are not interpolated; `jet_wp` is also never assigned. The defect is a malformed command rather than an evaluated Python `NameError` on that line. Also, although PicoProducer's README broadly says no tests use legacy modules, `Tests/PicoProducer/testSFs.py` explicitly imports the archived ROOT-based muon scale-factor class.
